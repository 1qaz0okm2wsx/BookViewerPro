# 架构设计

> 本文描述墨阁 BookViewer Pro 的分层架构、数据模型、存储设计与核心算法，供二次开发与技术评审参考。

## 1. 总体分层

```
┌─────────────────────────────────────────────────────────────┐
│  视图层 components/                                          │
│  Bookshelf · Reader · Converter · Editor · SvgEditor        │
│  NotesPanel · ExportPanel · ui · icons                      │
├─────────────────────────────────────────────────────────────┤
│  状态层 store.tsx（React Context + Hooks）                   │
│  书库 / 笔记 / 书签 / 进度 / 会话导出 / Toast / 路由视图      │
│  —— 所有集合变更后自动写入 IndexedDB ——                       │
├─────────────────────────────────────────────────────────────┤
│  服务层 lib/（纯函数，无 React 依赖，可单测）                 │
│  parse（11 格式解析） · convert（转换管线） · epub（EPUB 构建）│
│  domrange（选区偏移） · cover · exportZip · pdf · samples   │
├─────────────────────────────────────────────────────────────┤
│  存储层 lib/idb.ts（IndexedDB，idb-keyval 风格封装）          │
│  Blob 存书 · JSON 存笔记/书签/进度/书目 · 会话级内存缓存       │
└─────────────────────────────────────────────────────────────┘
```

**设计原则**

1. **解析结果统一为单一模型**：无论 EPUB、DOCX 还是 MOBI，解析器输出统一的 `ParsedBook`，阅读器/转换器/编辑器只面向该模型编程；
2. **服务层零 UI 依赖**：`lib/` 下全部为纯 TS 函数，视图层通过 `store` 间接调用，便于替换与测试；
3. **存储与状态解耦**：`store.tsx` 以 `useEffect` 订阅集合变化做持久化，组件无需感知 IndexedDB；
4. **优雅降级**：每个可能失败的环节（字体、封面、PDF worker、DRM 文件）都有独立 try/catch 与可读的中文错误提示。

## 2. 核心数据模型（`src/types.ts`）

### 2.1 书目 BookMeta

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | `crypto.randomUUID()` 生成，同时是 IndexedDB 文件键 |
| `title` / `author` | string | 导入时从文件名推断，EPUB/FB2 打开后以元数据为准 |
| `format` | BookFormat | `epub/pdf/docx/html/svg/txt/md/cbz/mobi/fb2/image` |
| `size` | number | 原始字节数 |
| `cover` | string? | Canvas 程序化生成的 dataURL（竖排书名封面） |
| `source` | `"user" \| "sample"` | 区分用户导入与内置示例 |

### 2.2 批注 Annotation（笔记系统的核心）

```ts
interface Annotation {
  id: string;          // UUID
  bookId: string;      // 关联书目
  chapterId: string;   // 关联章节（ParsedChapter.id）
  chapterTitle: string;
  type: "highlight" | "underline" | "strike" | "comment";
  color: string;       // 四色之一：松烟绿 / 朱砂 / 金 / 黛蓝
  text: string;        // 选中原文（截断 160 字，用于笔记列表展示）
  note: string;        // 用户批注文字
  start: number;       // ★ 章节纯文本流中的起始字符偏移
  end: number;         // ★ 结束偏移
  createdAt: number; updatedAt: number;
}
```

**为什么用字符偏移而不是 DOM 路径 / CFI？**
章节正文由解析器生成、结构稳定，「全文纯文本序列中的字符区间」是最健壮且可跨设备还原的定位方式：还原时只需对同一章节 HTML 重建后的文本节点树做一次线性扫描。该坐标随 ZIP 导出（`annotations.json`），具备可移植性。

### 2.3 其余模型

- `Bookmark`：`chapterIndex + percent`（章节型）或 `page`（PDF），附用户标签；
- `ProgressState`：每书一条，阅读器按 2% 节流写入；
- `ParsedBook`：解析器统一输出（见 §4）；
- `ExportedFile`：会话内转换成果（Blob 引用，不入 IndexedDB，避免配额浪费）。

## 3. 存储设计（IndexedDB）

`src/lib/idb.ts` 提供 `loadJSON / saveJSON / del` 三个原语，键位规划：

| 键 | 值 | 写入时机 |
| --- | --- | --- |
| `bv.books` | `BookMeta[]` | 增删书 |
| `bv.notes` | `Annotation[]` | 批注增删改 |
| `bv.marks` | `Bookmark[]` | 书签增删 |
| `bv.progress` | `Record<bookId, ProgressState>` | 阅读滚动/翻页（节流） |
| `bv.seeded` | `boolean` | 首次构建示例书库后置位 |
| `bv.file.<id>` | `Blob` | 导入时存入原始文件 |

**容量与策略**：IndexedDB 配额通常为磁盘的 60%+，Blob 直存无需 base64 膨胀；删除书籍时级联清理批注/书签/进度与文件键。转换成果（`ExportedFile`）仅保存在内存中，刷新即弃——这是有意为之：大文件重复落库会迅速吃满配额，用户需要时可在导出面板一并打包。

## 4. 解析引擎（`lib/parse.ts`）

### 4.1 统一输出

```ts
interface ParsedBook {
  kind: "chapters" | "pdf" | "image";   // 三种渲染路径
  chapters: ParsedChapter[];            // { id, title, html }
  pdfData?: ArrayBuffer;                // kind = pdf
  imageCount / imageDataUrl;            // kind = image（单图或 CBZ）
  cover?: string; wordCount: number; metaExtra?: Record<string,string>;
}
```

### 4.2 各格式管线

| 格式 | 管线 |
| --- | --- |
| EPUB | JSZip 解包 → `container.xml` 定位 OPF → 解析 manifest/spine → 按 spine 顺序读取 XHTML → DOMPurify 净化 → **图片解析相对路径转 dataURL** → 单章按 H1/H2 二次拆分 |
| CBZ | JSZip 解包 → 过滤 `__MACOSX` 与隐藏文件 → 自然排序（`localeCompare numeric`）→ 按需惰性取图（`getCbzImage(bookId, i)`） |
| DOCX | mammoth `convertToHtml`（图片自动内联）→ H1/H2 拆章 |
| TXT | 正则识别「第X章/节/回/卷」标题行拆章；无标题且超 1.2 万字时按段切块（每块 160 段） |
| Markdown | marked（`breaks: true`，**注意 v12+ 返回 Promise，必须 await**）→ 净化 → 拆章 |
| HTML | DOMParser 取 body → 净化 → 拆章；书名优先取 `<title>` |
| FB2 | 按 XML 解析（`parsererror` 检测）→ `<section>` 映射为章节，`<emphasis>` 等内联标签映射为 HTML |
| MOBI/AZW3 | 读 PalmDB 头（76 偏移取记录数）→ Record 0 读压缩方式/编码/书名 → **PalmDOC LZ77 变体解压**（0x00 直拷 / 0x01-0x08 字面量组 / 0x09-0x7F ASCII / 0x80-0xBF 双字节回引 / 0xC0+ 空格转义）→ 按 `textEncoding`（65001=UTF-8，1252=西文）解码 → HTML 拆章；`encryption != 0` 明确拒绝（DRM） |
| PDF | 不经文本解析，直接缓存 `ArrayBuffer` 交 pdf.js 渲染（`kind: "pdf"`） |
| SVG/图片 | `FileReader.readAsDataURL` 单图模式 |

### 4.3 安全净化

所有外部 HTML 必经 `sanitizeAndInline()`：DOMPurify 白名单清洗 → 移除 `script/style/iframe/link` → 非 dataURL 图片尝试经资源解析器内联，失败即移除。批注工具条写入的 `<span>` 不受影响（白名单内含 span）。

## 5. 阅读器两大机制

### 5.1 CSS 多列分页

正文容器使用 `column-width / column-gap`，横向滚动容器以 `transform: translateX(-page × (colW + gap))` 定位当前页：

- 页数 = `scrollWidth / colWidth`（60ms 防抖测量，监听 resize / 字号 / 行距 / 搜索 / 批注重包）；
- 批注以 `<span class="bv-ann" data-aid>` 包裹文本节点实现；**每次重包前先 unwrap + normalize 归一化**，避免重叠批注嵌套导致文本节点树漂移、偏移坐标失效；
- 键盘 ←/→ 翻页，进度 = `(chapterIdx + page/(pages-1)) / chapters.length`。

### 5.2 批注生命周期

```
选中文本 mouseup
  → selectionToOffsets() 计算字符区间（TreeWalker 线性扫描）
  → 光标处弹出工具条（4 色 × 4 类型）
  → addAnnotation() 落库
  → 渲染 effect：unwrapAll → 按 start 排序逐条 wrapRange（先包被包含者）
  → 点击批注弹层：改颜色 / 写批注 / 删除
重开书籍 → 同一 effect 自动还原 → 笔记中心「回跳」经 data-aid 定位并闪烁
```

## 6. 转换管线（`lib/convert.ts`）

`targetsFor(format)` 返回目标矩阵 → `convertFile(meta, blob, key, onStage)` 分两段：

1. **解析段**：复用 `parseBook` 得到章节模型（PDF/SVG/图片类源跳过）；
2. **生成段**：
   - **PDF 输出**：离屏 iframe（A4 宽度 794px）排版 → `html2canvas` 2× 光栅化 → jsPDF 按页高分片写入。光栅化方案对中文零字体依赖，体积换兼容性；
   - **DOCX 输出**：`docx` 库按段落/标题映射构建；
   - **EPUB 输出**：自研构建器（见 §7）；
   - **CBZ→PDF**：首图定页面比例，逐页 `addPage([w,h], orientation)`。

转换全程经 `onStage` 回调向 UI 播报阶段文案，成果同时进入会话导出列表供 ZIP 打包。

## 7. EPUB 构建器（`lib/epub.ts`）

浏览器端生成**合规的 EPUB 2/3 包**：

- `mimetype` 以 `compression: STORE` 置首（规范强制）；
- `META-INF/container.xml` → `OEBPS/content.opf`；
- EPUB 3 写 `nav.xhtml`（`properties="nav"`）+ `dcterms:modified`，EPUB 2 写 `guide` + `meta[name=cover]`；两者均附 `toc.ncx` 保证阅读系统兼容；
- 章节切分：编辑器另存时按 H1 分组，阅读器转换时直接沿用解析章节；
- 封面 dataURL → `cover.jpg` 内嵌。

## 8. 错误处理与韧性

- **ErrorBoundary**（`App.tsx`）：任何渲染异常渲染中文诊断面板（错误信息 + 堆栈 + 重载），杜绝白屏；
- **index.html 错误上报**：`window.onerror` 向宿主 postMessage，便于沙箱环境诊断；
- **模块级降级**：封面生成失败 → 色块占位；字体加载超时（800ms race）→ 系统宋体；DRM 文件 → 明确拒绝文案；
- **Toast 三态**：成功（墨绿）/ 错误（朱砂深底）/ 提示（纸色），3.4s 自动消散、点击即关。

## 9. 性能考量

| 场景 | 策略 |
| --- | --- |
| 大 TXT 分章 | 按标题行流式切分，单章上限约 160 段 |
| CBZ 大图 | 惰性解码，仅当前页读取为 dataURL |
| 搜索高亮 | 仅重渲当前章节，`search.version` 触发分页数重测 |
| 进度写库 | 滚动按 2% 增量节流，避免每帧写 IndexedDB |
| 解析缓存 | `parsedCache` 内存级缓存，同一书二次打开零解析 |
| 首屏体积 | pdf.js worker 独立 chunk（`?worker`），主包 gzip ≈ 680KB |
