# 开发指南

> 面向二次开发者：环境搭建、目录职责、实现要点、踩坑记录与扩展教程。

## 一、环境要求

- **Node.js ≥ 18**（推荐 20 LTS），Windows 下用 nvm-windows 管理多版本；
- **npm ≥ 9**（随 Node 附带）；
- 编辑器推荐 VS Code + 插件：ESLint、Tailwind CSS IntelliSense、Prettier。

```powershell
npm install        # 安装依赖
npm run dev        # 开发服务器（HMR）
npm run build      # 生产构建 → dist/
npm run preview    # 预览生产构建
npm run typecheck  # TypeScript 全量类型检查
```

## 三、实现要点

### 3.1 状态层约定

- 所有集合（books/annotations/bookmarks/progress）在 `AppProvider` 内以 `useState` 持有，`useEffect` 监听变化写入 IndexedDB——**组件只调 `useApp()` 的方法，绝不直连 idb**；
- `pendingJump` 是一次性消息：笔记中心写入 → 阅读器消费并清空。跨视图通信统一走这个模式；
- Toast 自动清理计时器存于 `timers` ref，Provider 卸载时统一清理，防止内存泄漏。

### 3.2 阅读器 effect 依赖表（调试时最常查）

| Effect | 依赖 | 作用 |
| --- | --- | --- |
| 打开书籍 | `book?.id` | 解析 + 恢复进度 |
| pendingJump 消费 | `pendingJump, parsed` | 同书二次回跳 |
| 分页测量 | `mode, chapterIdx, annVersion, search.version, parsed, colW, fontSize, lineHeight` | 计算页数、恢复页号 |
| 跳转请求 | `parsed, chapterIdx, annVersion, mode, search.version` | 批注定位 / 百分比恢复 |
| 批注包裹 | `parsed, chapterIdx, bookAnnos, annVersion, mode` | 解包 → 排序 → 重包 |

`annVersion` 是手动重包开关：任何外部导致的章节重渲（搜索、跳转、批注增删）都通过它强制 effect 重跑。

### 3.3 富文本编辑的光标问题

`contentEditable` 容器**不能**用 `dangerouslySetInnerHTML` 受控回写——React 每次 render 重置 innerHTML 会使光标跳到末尾。本项目的解法（`Editor.tsx`）：

```ts
const skipWrite = useRef(false);
const syncFromDom = () => { skipWrite.current = true; setDocHtml(el.innerHTML); };
useEffect(() => {
  if (skipWrite.current) { skipWrite.current = false; return; }  // 输入引发 → 不回写
  el.innerHTML = docHtml;                                         // 外部变更（切页签/载入）→ 回写
}, [docHtml, tab]);
```

## 四、踩坑记录（真实发生过的）

| # | 现象 | 根因 | 解法 |
| --- | --- | --- | --- |
| 1 | dev 模式白屏：`pdf.worker.min.mjs?url does not provide an export named 'default'` | Vite dev server 把 node_modules 内的 `.mjs?url` 当 ES 模块伺服，worker 无 default 导出 | 改 `?worker` 后缀 + `GlobalWorkerOptions.workerPort` |
| 2 | `marked.parse(...).replace is not a function` | marked v12+ 的 `parse` 返回 Promise | 一律 `await marked.parse(...)` |
| 3 | 批注重开后位置漂移、嵌套包裹 | 重包前未清理旧 span，文本节点树变化导致偏移失效 | 每次应用前 `unwrapAll + normalize` 归一化 |
| 4 | 批注工具条定位偏移一整个侧栏宽度 | 坐标基准用了全屏 shell 而非阅读区 | 统一以阅读区容器 `getBoundingClientRect` 为基准 |
| 5 | MOBI 解析 RangeError | 坏文件记录偏移倒挂时 `Uint8Array` 长度为负 | 三重钳制：负值归零 / 4096 上限 / 不越界 |
| 6 | PDF 句柄 `doc.destroy()` 类型报错 | 新版 pdf.js 将 destroy 移至 loadingTask | `await task.destroy()` |
| 7 | 滚动模式每帧写 IndexedDB | onScroll 未节流 | 按 2% 增量节流 |

## 五、扩展教程：新增一种格式

以「支持 RTF 阅读」为例，三步完成：

**① `src/types.ts`**：`BookFormat` 联合类型加 `"rtf"`，补 `FORMAT_LABEL` 与 `FORMAT_COLOR`。

**② `src/lib/parse.ts`**：
- `detectFormat()` 映射表加 `rtf: "rtf"`；
- `parseBook()` switch 增加 case：解析为 HTML 后走既有管线——

```ts
case "rtf": {
  const text = await readAsText(blob);
  const html = rtfToHtml(text);            // 你实现的转换函数
  const clean = await sanitizeAndInline(html, noResolver);
  const chapters = splitHtmlByHeadings(clean, fallbackTitle);
  result = { kind: "chapters", format: "rtf", title: fallbackTitle, author: "—",
             chapters, imageCount: 0, wordCount: wordCountOf(chapters) };
  break;
}
```

仅此一步，**阅读器、编辑器载入、笔记、ZIP 导出立即全部可用**——这是统一 `ParsedBook` 模型的红利。

**③ `src/lib/convert.ts`**（可选）：`targetsFor()` 加 `case "rtf": return [T("html", ...), T("txt", ...)]`，`convertFile()` 复用章节生成器即可，无需新代码路径。

## 六、构建与体积

- 主包 gzip ≈ 680KB（含 docx/jspdf/html2canvas/turndown），pdf.js worker 独立 chunk ≈ 1.2MB；
- 如需进一步优化，可在 `vite.config.ts` 配置 `build.rollupOptions.output.manualChunks` 将 `jspdf + html2canvas` 拆为按需 chunk，并把 Editor/Converter 改为 `React.lazy` 路由级分包；
- GitHub Pages 部署已由 workflow 通过 `--base=./` 处理相对路径，本地 `npm run build` 默认绝对路径 `/`。

## 七、调试技巧

- **查看本地数据**：DevTools → Application → IndexedDB → `bookviewer-pro-kv`；
- **重置示例书库**：删库后刷新，`bv.seeded` 缺失会重新构建；
- **构造测试书**：`docs/` 未附带样本文件，可用编辑器「存回书架」快速造 HTML 书，或把任意 `.zip` 改名 `.cbz`（内含图片）测试漫画管线；
- **批注偏移验证**：导出 ZIP 中的 `annotations.json` 与 `原书` 配对，即可在另一台机器验证还原精度。
